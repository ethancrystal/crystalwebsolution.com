# CRM Client Collaboration: Jobs-to-be-Done (JTBD)

## User Persona: Client Owner (Active Project Partner)
* **Who**: Startup founder, corporate manager, or product lead hiring CWS for a cinematic web experience.
* **Goal**: Build and launch their web application on schedule while maintaining absolute clarity on milestones, deliverables, and outstanding action items.
* **Context**: Often busy, checking updates on both desktop and mobile, requiring clear and structured communication rather than tracking down files in long email chains.
* **Success Metric**: Zero missed feedbacks, clear timeline tracking, and zero friction in sharing project assets.

---

## Job Statements

### 1. Project Visibility & Milestone Tracking
When my digital project is active, I want to see a single source of truth for current milestones, completion dates, and project state, so I can plan my own launch and report status to stakeholders with confidence.

### 2. Efficient Asset Exchange & Approval
When a design mockup or technical artifact needs my approval or input, I want to securely upload/download files directly inside my dashboard and mark items as approved, so the delivery team is never blocked on my feedback.

### 3. Progressive Communications
When a project manager changes a task or updates a phase, I want to get real-time, context-focused status changes within the portal, so I don't have to scroll through messy email threads or Slack channels.

---

## Current Solutions & Pain Points
* **Incumbent Solution**: Back-and-forth emails, Google Drive links, scattered Slack messages, and manual PDF status updates.
* **Pain Points**:
  - Files get lost in threads; version control is difficult.
  - Clients are unsure what is "active" versus "approved".
  - Misaligned expectations about timeline progress.
* **Consequence**: Delays in project delivery, client anxiety, and unnecessary coordination overhead.
